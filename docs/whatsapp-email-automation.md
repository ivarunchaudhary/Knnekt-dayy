# WhatsApp + Email Automation (Knnekt)

Status doc for any Claude session working on this. Read it first, then update the **Status**, **Blockers**, and **Change log** sections whenever something changes.

Last updated: 2026-10-31

## Goal

Automate WhatsApp and email messages for Knnekt's first launch, replacing AiSensy:
- Form submit on the website → confirmation email + WhatsApp template message
- Later: inbound WhatsApp replies (STOP handling, keyword replies)

## Decisions so far

- **Automation platform:** Make.com. Free plan for build and testing, paid tier expected before live volume.
- **WhatsApp channel:** Meta WhatsApp Cloud API connected directly to Make (no third-party WhatsApp SaaS, to avoid platform fees). AiSensy is being replaced.
- **Email:** sending method not chosen yet. Options: reuse the existing `sendMail` helper used by the contact route, or a transactional provider (Resend/SendGrid) with SPF/DKIM/DMARC set up.
- **Consent:** every WhatsApp recipient must opt in. Add a consent checkbox to website forms and store timestamp with the lead.
- **Messaging categories:** start with utility templates (confirmations, reminders). Marketing templates cost more and come later.

## Key facts (verify before relying on them)

- Make free plan: about 1,000 operations/month, polling interval of 15 min or more, limited active scenarios (one source says 2). Confirm on Make's pricing page.
- Make has a native WhatsApp Business Cloud app with "Send a Template Message". Free-form messages only work after a customer replies to a template.
- Meta bills per message (marketing, utility, authentication). Non-template service messages reportedly metered from 1 Oct 2026 (1,000 free per number/month). Sources conflict on India rates. Check Meta's rate card before budgeting.
- A payment method must be on the WhatsApp Business account, or messages fail even if Make reports success.

## Email automation

Source of truth for the copy and codes: Notion → Knnekt OS → Message Templates (Channel = Email) and Cohort 01 Pipeline → Message codes. The PDF checklist (`Knnekt_Pipeline_Messaging_Build_Checklist.pdf`, section 4) says Gmail, but Notion and the code use Resend; we went with Resend (already wired, domain sender hello@knnekt.studio, studio copy by BCC).

**How it works:** Make decides *when* (stage changes and the "Messages sent" log on the founder's row), the site decides *what*. Make calls `POST /api/email` with `Authorization: Bearer <EMAIL_API_SECRET>` and `{ "code", "to", "vars", "dryRun"? }`. The route fills the Notion copy, formats every date in IST, attaches files, sends through `lib/mailer.ts`. Make adds the code to "Messages sent" only on a 200 with `sent: true`.

Files: `app/api/email/route.ts`, `lib/cohortEmails.ts` (templates), `lib/ics.ts` (calendar invite), `lib/letter.ts` (shared letter layout, also used by E1 in `lib/scoreEmail.ts`).
